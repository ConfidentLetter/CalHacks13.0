Message from Henry: avf works when it is the only client, but the Desk View virtual camera serves ONE ffmpeg at a time, and your ffmpeg child outlives the Python process that started it: after a server restart the old ffmpeg (started under nohup) kept the device and every new AvfDevice got "no frame within 5 s". Please (1) start ffmpeg in its own process group and register atexit + signal handlers so it dies with the parent, and on start-up kill any leftover `ffmpeg … -f avfoundation` processes from a previous run of this repo (match the full command line you generate, e.g. by writing a pid file under runtime/avf.pid); (2) if the first frame does not arrive within 5 s, retry once after killing stale ffmpeg; (3) never spawn a second stream for the same device within one process — test scripts and the server must share it. Also note: two Python processes (an eval script and the server) cannot both hold the Desk View camera; document that in hardware/README.md.
