## For other terminals

- **T3 / T5:** `perception_detect.build_twin(frame_path)` runs the REAL pipeline now (T1 calibrate/tile/wires/nets + my Tier A components). With no registrations it returns a valid twin with `components: []`. Set `BM_MOCK=1` to get `mocks/twin_ok.json` content instead (demo backup). `frame_id` is `f_` + sha1 of the file bytes. If a T1 stage raised, the twin carries an extra `errors: {stage: message}` key (schema allows extra keys) — T5 may show it as a status line.
- **T5:** `build_twin` caches by frame hash; `register()` clears the cache, so the next twin after a click reflects it. Twins also carry `source: "tier_a"|"tier_b"` per component.
- **T5 (click-to-register UX):** one click per footprint row on the FIRST pin: BME280 = 1 click (VIN), ESP32 DevKit = 2 clicks (3V3 pin of row 0, then GND pin of row 1). The second row's direction is inferred automatically to overlap the first row; an optional click on the last pin (`end_pixel`) overrides.
- **T5:** Tier B is on by default (weights are cached on this laptop). Call `perception_detect.owl.warmup()` in a background thread at server start — it takes ~20 s (model load + one dummy inference) and without it the first twin takes 10+ s. `BM_TIER_B=0` gives a Tier-A-only demo at ~110 ms per twin; that is the safe fallback if the laptop is busy. Unknown Tier B boxes come back as components with `part_id: null`, `pins: []`; `perception_detect.components.last_needs_register()` gives `[{element_id, prompt}]` you can forward as a `confirm_request`/register prompt.
- **T5:** your `mock_register` writes the same `runtime/registrations.json` in a compatible shape (I only need `part_id`, `row_index`, `pixel`), so switching between mock and real register is safe.
- **T5 (calibrate message):** call `perception_detect.geometry_bridge.set_manual_corners(corners)` with the 4 clicked points (TL, TR, BR, BL of the main grid: A1, A63, J63, J1); I pass them to T1's `calibrate()` whenever markers are not enough. It also clears my twin cache. If calibration fails on a frame (hand over a marker) I reuse the last good homography; the twin carries `calibration: "markers_or_corners" | "last_good" | "identity"` — show a hint when it is not the first.
- **T5:** registrations are stored as HOLES (snapped at click time), so camera drift between frames does not invalidate them. `perception_detect.tier_a.stale_registrations(H)` lists the ones whose click pixel now maps elsewhere (camera or part moved) — still used, but you may prompt "re-click?".
